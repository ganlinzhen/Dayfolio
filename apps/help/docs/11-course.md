## 页面操作区

课程详情以紧凑的课程名称与阅读进度标识当前内容。课程总览和讲义阅读页只在正文容器的操作栏显示标题、状态和全屏操作，避免上方再重复一遍。

课程总览和讲义正文随阅读区域宽度自适应展开，内容区水平居中、左右留白对称，段落保持左对齐；切换全屏后会重新适配。已导入课程同样适用，无需重新导入，不改变阅读、自测和样课确认状态。

计划中进入一项学习安排后，可在当前详情直接阅读当天完整课件、核心概念和源码导读，并在「评测」区提交自测。课程阅读页与学习详情共用阅读和自测记录；提交后展示解析，作答属于学习痕迹，不自动代表掌握或完成安排。

## 课程从哪里来

正式 App 随附「Dayfolio 上手之旅」：安装后首次启动会自动导入，已有用户升级后也会在下一次启动补入。在「学习」页顶部点击「上手课程」即可打开，也可切换到「课程」列表找到它。当前提供独立总览和第 1 天样课，不自动创建学习计划或待办，也不会替你确认样课。

若课程库中已有相同标识的上手课程，启动时保留原课程，不覆盖讲义、阅读、自测、样课确认或计划绑定。后续内容更新仍使用课程导入流程；随包内容更新不会自动覆盖已经收录的版本。

课程由 AI agent 通过 MCP `import_course` 导入**课程包**（一个含 `course.json` 清单、**独立课程总览 HTML** 与逐日讲义 HTML 的目录）。**总览应单独生成，不算 D1，不占课程天数；D1 只写第一天教学内容。**新课程包在 `course.json` 中声明 `schema_version: 2` 与 `overview: { "html": "overview.html" }`，`lessons` 则只列 D1..Dn；v2 缺少独立总览会被拒绝。未声明版本的旧课程包仍可导入，缺总览时 App 显示「待生成」。包内每课包含：可直接阅读的正文、核心概念、实例、自测题与答案解析、来源；针对仓库的课程还带**源码导读**（代码路径 / 关键符号 / 作用 / 建议阅读顺序——纯文本参考，绝不执行命令）。

讲义资产存放在应用数据目录的 `courses/<课程slug>/` 下（与数据库同根推导，不放 `.app` 或桌面固定路径）；导入时做**路径穿越与符号链接（symlink）拒绝**、**HTML 消毒**（剥 script / 事件属性 / javascript: 等危险协议，并**中和外部资源**——http/https 外链图片等一律失效，讲义必须离线自包含）。讲义引用的**包内样式表**（如 `<link rel="stylesheet" href="../assets/style.css">`）会在导入时**内联为离线 `<style>`**：课程的排版样式（横幅、提示框、表格、代码块等）得以保留；CSS 中的 `@import` 与外部/绝对 `url()` 一律移除，指向包外或外部地址的样式引用直接剥除——讲义始终离线自包含。App 渲染再加 iframe sandbox + CSP 双保险（正文不加载任何外部资源）。

绑定的学习计划只能**引用已存在的计划**（`plan_id` 不存在时导入拒绝），绝不重复创建。计划可先创建，后续导入样课时再绑定；已导入但尚未绑定的课程，也可以在课程包中补上该计划的 `plan_id` 后重导**同版本同内容**的样课包完成绑定。已绑定课程不能换绑其他计划。

若无日期学习草案已指定这门课程，确认生成正式计划时会自动绑定，保存或排期草案时不会提前绑定。旧版已确认草案若漏写关联，可由助手重复确认原草案补齐空绑定，复用原计划和待办；这不会改变课程内容、阅读、自测或样课确认，已有其他计划绑定时拒绝改绑。

**导入的可靠性规则**：

- **课程必须从样课开始**：任何课程包都必须**恰好包含一个 `is_sample` 样课标记**——去掉标记的包（哪怕只有一天）直接拒绝；首次导入只接受样课包（仅样课一天），直接导入完整包会被拒绝——完整版只能经「确认 → 请求 → 认领」流程导入；
- **失败不留孤儿**：资产先复制到位、数据库后写入、最后原子换入——任何一步失败，课程表不会残留「有记录无文件」的孤儿行；
- **幂等且可自修复**：重复导入同内容无变更；若磁盘讲义文件丢失或与记录不一致，重导同一课程包会**自动修复**；
- **重导保留进度**：内容未变的天保留已读状态与自测作答；内容变更的天重新开始；
- **样课包重导不删已生成天**：完整版就绪后再导入样课包，只更新样课那天——库记录与磁盘上其余各天的讲义文件都原样保留；
- **独立总览可后补**：旧课程包没有 `overview` 时，App 显示「课程总览待生成」，不会将 D1 当成总览；agent 可为样课包新增 `overview.html` 并重导，同内容的 D1 保留已读、自测和样课确认。总览与日课不能共用 HTML 文件；已有总览的课程导入完整包时须保留总览文件；
- **计划绑定不可改**：课程绑定学习计划后，后续任何导入（样课重导或完整包）都**不能换绑其他计划**（省略 `plan_id` 表示沿用原绑定）。

## 课程总览与每日卡片

课程没有独立的侧栏入口，学习入口统一为**「学习计划」**。首页头部左侧的**「计划 / 课程」**切换默认显示计划，课程页集中显示所有课程（包括未关联计划的课程）；计划卡显示关联的课程名称，尚未关联时显示「待关联课程」。从课程页点击课程可进入总览；已关联的课程，也可从计划详情的**「进入课程总览」**按钮或每日摘要卡（直达当天讲义）进入。课程总览返回课程页时保留原来的视图。计划最终应关联课程，但允许先规划、后导入课程。

课程页面先展示一张**独立课程总览卡**，点击可阅读单独生成的总览正文；它不计入日课或已读讲义进度。下方「每日课程」仍是**每日一张卡片**——日期 / 第几天、主题、知识概要（核心概念名）、预计时长、阅读状态。已生成与未生成的天**按天数顺序混排**（缺口天显示在其真实位置，不会堆到末尾）；头部计数为**「已读讲义 a/已生成 b · 计划 N 天」**——绑定五天计划而只生成两天时显示「已读讲义 1/2 · 计划 5 天」，不会把总览算成一天。点击日课卡进入当天完整讲义，返回课程页面时进度与滚动位置保留；从每日摘要卡直达讲义的，返回直接回到计划详情原位。未生成的天明确显示**「待生成」**。课程关联既有学习计划只引用、不重复创建计划；原计划的进度与打卡不受影响。

## 每课版本

每张日课卡片、计划详情的讲义摘要及讲义阅读页显示本课版本（v1、v2、v3…）。新课从 v1 开始，导入更新后由服务自动递增；正文、概念、源码导读、自测或预计时长发生实际变化时，只增加对应课次的版本。重复导入相同内容、修复丢失文件、仅变更课程包版本以及阅读、答题、确认样课均不增加课次版本。

已有讲义在升级后从 v1 开始记录，不推算历史更新次数；独立课程总览不计入逐课版本。课次版本独立于课程包的版本字段，由 App 和 MCP 共用服务维护，不能通过课程包自行指定。原有阅读、自测及样课确认规则继续适用。

## 讲义阅读与自测

每课在 App 内直接阅读消毒后的讲义 HTML，正文工具栏可切换「全屏」（占满侧边栏右侧内容区）；下方是核心概念、源码导读与**自测**。作答选项超出题目范围会被拒绝；提交后可显示答案解析——**答题是学习痕迹，不是掌握证据**：掌握判定仍走「学习闭环」的测评（`record_study_assessment`），内容生成与答题都不算掌握。

课程尚未确认时，日课卡片显示「样课」标识，讲义页提示回到对话确认。确认当前版本后，两处提示立即隐藏；内容变化导致确认过期时恢复显示。此显示变化不删除课程包的样课信息，也不改变阅读、自测或生成校验。

## 样课确认与完整版生成（关键流程）

1. agent 导入**样课**（课程包中标 `is_sample` 的一课；首次导入只接受样课包）；
2. 你在 App 内**阅读样课**（打开讲义自动记录已读），看完后回到对话说「样课确认」；助手通过专用工具 `confirm_course_sample` 记录你对当前内容版本的明确同意，**无需在 App 点击确认**。未阅读不能确认；内容变更后须重新阅读并确认；
3. 若希望继续，直接说「样课确认，继续生成完整版」；助手记录确认后创建生成请求并继续认领处理。只说确认样课时仅记录确认，不自动请求生成。请求创建后仍需助手实际执行，App 负责展示进度；切回 App 会同步课程状态，不打断当前阅读或自测；
4. agent 通过 MCP `list_course_requests` 发现待执行请求 → `claim_course_request` 认领 → 在 Dayfolio 外编写完整课程包 → `import_course` 导入 → `complete_course_request` 完成。

**安全规则**：

- 样课内容变更会使确认**过期**（须重新确认，旧版本的生成请求拒绝执行）；
- **完整包不能绕过确认与请求队列**：首导完整包直接拒绝；对已走样课流程的课程，只有存在你确认后、且 agent 已认领（claimed）的生成请求时，完整包才允许导入——直接 import 会被拒绝。唯一例外：课程**已完成**后重导**完全相同内容**（同版本同哈希）的完整包不需要再认领——用于幂等重试与磁盘文件丢失后的自动修复；任何内容变化仍须走「重新确认 → 新请求 → 认领」；
- **完整包的样课正文须与确认版本逐字节一致**：认领后生成的完整包，其样课天的内容若与你确认的版本不同（被偷换），**导入时即被拒绝**——不会等到完成核验才发现，更不会冲掉你的确认；
- `complete_course_request` 完成前会核验**确认哈希未过期**与**天数完整**：绑定计划的课程须覆盖计划全部天数（五天计划就要有第 1..5 天），未绑计划的须第 1..N 天连续无缺口——拿残缺版本冒充完整版会被拒绝；绑定计划已被删除时同样拒绝（删计划或换绑短计划不能掩护短包）；
- 生成请求的**排队与执行严格区分**。

## 删除课程

在课程详情右上角点击「删除课程」，确认后永久删除该课程的独立总览、全部讲义、阅读与自测记录、生成请求和课程资产，并解除学习草案对课程的引用。删除不可恢复；课程已就绪或已有阅读记录时同样适用。

计划与课程分别管理：单独删除课程会保留学习计划和待办。若要整组清理，可在对话中指定计划、课程及关联待办，确认范围后让助手分别调用专用删除工具；删除计划默认连删该计划独占的自动待办及打卡，也可明确保留待办。

助手先用 `list_courses` 核对 ID、slug 和标题，再用 `delete_course`（course_id、expected_slug）执行；目标标识不一致时拒绝。删除数据库记录失败时恢复原资产；若记录已删除但资产清理失败，会明确提示隔离资产的剩余位置。

## 让 AI 帮你

- 「导入课程样课包」（`import_course`）
- 「删除课程 X」——核对目标并确认不可恢复后删除（`delete_course`）
- 「看看有哪些课程」「查看第 X 天讲义」（`list_courses` / `get_course_lessons` / `get_lesson_html`）
- 「查看课程总览」「给旧课程补一份独立总览」（`get_course_overview` / `import_course`，后者在样课包里加入 `overview.html`，D1 内容保持原样才不会使样课确认过期）
- 「提交第 X 天自测答案」（`submit_lesson_quiz`）
- 「样课确认」——阅读后在对话中明确同意，由助手记录当前版本（`confirm_course_sample`）
- 「样课确认，继续生成完整版」——助手确认后继续创建请求、认领、生成与导入（`confirm_course_sample` → `create_course_request` → claim → 生成 → import → complete）
- agent 值班：「查一下有没有待处理的课程生成请求」（`list_course_requests` → claim → 生成 → 导入 → complete）


## 本体浏览与确认

课程、讲义、独立总览和生成请求均可统一浏览。导入、阅读、自测与生成仍走原业务服务；样课在 App 阅读后可在对话中明确确认，由专用工具记录当前版本；通用动作不提供审批能力。删除绑定计划后课程仍受原完整性检查限制。
