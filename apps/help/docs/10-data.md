「数据」面板是整个 App 的数据中枢：用**本体**的方式统一描述和管理所有数据——类似「这个应用里有哪些种类的数据、它们之间有什么关系、可以对它们做什么操作」。

## 六个视图

面板左侧的目录包含六个视图：

| 视图 | 作用 |
| --- | --- |
| 总览 | 一屏看清全部数据存储：SQLite 主库大小/迁移版本/逐表行数、工具箱文件占用 |
| 对象 | 按对象类型浏览实例数据，点行看详情（属性 + 链接关系 + 运行动作） |
| 对象类型 | 管理对象类型（ObjectType）：新建类型、增删属性 |
| 链接类型 | 管理链接类型（LinkType）：定义类型之间的关系 |
| 动作类型 | 管理动作类型（ActionType）：定义可执行的数据操作 |
| 维护 | 备份数据库、导出 JSON、完整性体检、VACUUM 压缩 |

## 本体三要素

- **对象类型**：一类数据的结构（属性、主键、标题属性）。系统内置 8 个类型（待办、学习计划、计划条目、打卡、新闻、工具、工具分类、天）；你可以创建自己的类型（如「书」「笔记」），会自动建表；
- **链接类型**：两个对象类型之间的关系。一对多用外键属性承载，多对多用一个中间表对象承载。内置链接描述了计划→条目、待办→打卡等关系；
- **动作类型**：一组「参数 + 写规则」的可执行操作。内置动作绑定核心业务（完成待办会联动打卡）；自定义动作由你拼装规则：创建/修改/删除对象、建立/解除链接，执行时在同一事务内完成，要么全成要么全回滚。

## 管理规则

- **系统类型**（内置的 8 个）：可以**追加可空属性**（自动加列），内置属性与类型本身受保护不可删改；
- **自定义类型**：完全可管理——加属性、删属性（连同该列数据）、删除整个类型（需输入 apiName 确认，表与数据一并删除）；
- 有链接或动作引用的对象类型/属性，需要先删掉引用方才能删除；
- 内置动作不可删除，但可以**停用**（停用后在对象详情与 MCP 中都不可执行）。

## 对象浏览与运行动作

在「对象」视图选择类型后可以搜索、翻页；点任意一行打开详情：

- **属性**：该对象的全部字段值；
- **链接**：出链（它引用了谁）与入链（谁引用了它），点击可跳转到对方对象；
- **运行动作**：选择一个动作并填参数，可直接对当前对象执行（若参数名为 `id` 或 `<类型>_id` 会自动预填本行主键）。

## 维护操作

- **备份数据库**：使用 SQLite 在线备份（`VACUUM INTO`），备份期间不影响 App 与 MCP 的正常读写，产物在 `userData/Backups/`；
- **导出 JSON**：类型元数据 + 全部实例数据导出为一个 JSON 文件，适合归档或迁移；
- **运行体检**：完整性检查（integrity_check）与外键一致性检查；
- **压缩主库**：VACUUM 回收空间。

## MCP 联动

数据面板里创建的类型与动作对 AI 同样可用，MCP 共提供 12 个本体工具（详见「MCP 与 AI 接入」）：

- **查询**：`list_object_types`（全部类型/链接/动作定义）、`query_objects`（按类型查实例）、`get_object`（单对象详情含链接关系）；
- **实例 CRUD**：`create_object` / `update_object` / `delete_object`（任意类型，含自定义类型）；
- **类型管理**：`create_object_type` / `update_object_type` / `delete_object_type`、`create_link_type` / `delete_link_type`、`create_action_type` / `update_action_type` / `delete_action_type`；
- **执行**：`invoke_action`（内置或自定义动作，单事务）。

你自定义了一个「记读书」动作后，直接对 AI 说「帮我记一笔读书」即可；也可以让 AI 自己建类型——「帮我建一个读书笔记类型，要书名/评分/心得字段」。
