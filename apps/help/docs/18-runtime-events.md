## 当前支持

App IPC 与 MCP 共用 core 的事件和订阅服务。已经登记的来源可以导入定时、全天和时间待定事件；单事件订阅会创建或复用唯一待办。来源改期、取消和恢复都沿用稳定事件身份。

工具箱已经统一为 HTML 导入和删除，不再提供工具包安装、启停、卸载或版本回滚接口。HTML 页面不会自动获得事件读写权限。

历史事件来源与订阅通过 App、MCP 共用的业务接口继续维护。移除旧工具入口不会删除个人待办、完成记录和订阅历史；HTML 资料页的更新与来源数据导入分别处理。

定时事件必须带 Z 或偏移，保存 UTC 事实；全天使用左闭右开的日期区间，不转换成 UTC 零点；时间待定不能猜测日期。统一显示时区持久保存在数据库中，两个入口共用。

## 用户修改保护

修改标题或排期即手动接管；备注、优先级和标签仍可跟随。已完成待办不会被来源刷新重开。取消订阅选择保留时转为基础待办；删除仅允许未完成记录。直接删除关联待办会停止跟随，后续刷新不会复活。

恢复跟随会应用当前来源标题及排期，需要先读取最新来源和待办修订。修订冲突后应重新核对。分类隐藏不会取消订阅；主动隐藏后新订阅也不会覆盖偏好。

## 来源刷新

历史日历来源的操作区可以请求刷新。按钮提交后立即返回排队状态，只有成功导入后才更新「最近成功」；重复点击会复用同一来源的有效请求。

HTTPS JSON 来源由正在运行的 App 或 MCP 拉取并按既有来源配置映射，无须新增专用宿主命令。App/MCP 均未运行时不会同步；重新运行后最多补一次到期刷新。来源失败、空响应和无效批次不会清空已有事件，状态会保留错误供重试。历史来源不可用或撤权后，旧请求不能继续提交。

需要外部助手核验的标准导入来源显示「等待外部助手核验并导入」。这只创建更新请求，不会自动运行 AI；外部助手提交有效标准事件后才完成请求。使用这类工具时，需让已连接 Dayfolio 的助手查看来源状态并完成导入。

日历「新建日程」旁的更多菜单 →「管理分类」可以勾选分类的显示范围；隐藏分类不会取消订阅或删除待办。系统分类及由事件来源维护的分类不能单独删除，可隐藏；HTML 工具的自定义分类可确认删除，已有待办保留并转入基础待办。
