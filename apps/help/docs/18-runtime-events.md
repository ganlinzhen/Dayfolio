## 当前支持

App IPC 与 MCP 共用 core 的事件和订阅服务。已经登记的来源可以导入定时、全天和时间待定事件；单事件订阅会创建或复用唯一待办。来源改期、取消和恢复都沿用稳定事件身份。

工具箱中的「安装或更新工具包」会先校验包，再展示版本、日历分类、权限和网络来源。确认后才安装。新权限必须在 App 的可信预览中审阅，MCP 不能自行授予。相同版本不允许替换为不同内容。

工具页面使用独立来源和有限 SDK，不能直接取得全部待办、原始 IPC 或数据库。工具箱、日历的打开工具操作和帮助目录从当前工具版本动态生成；安装新工具不需要重新生成内置帮助或重新打包宿主。

停用和卸载入口保留事件、分类、订阅与待办。回滚页面不会回退来源更新、个人修改或已完成记录；回滚涉及新增权限时，需要重新从工具包预览并授权。完整导航、重新加载、版本或权限变动后旧工具会话失效。

工具的订阅写权限与事件读取权限独立检查。订阅、取消和恢复只处理自身获授权来源，并返回必要的待办摘要；独立查询仍需要读取权限，个人备注和标签不向工具返回。

定时事件必须带 Z 或偏移，保存 UTC 事实；全天使用左闭右开的日期区间，不转换成 UTC 零点；时间待定不能猜测日期。统一显示时区持久保存在数据库中，两个入口共用。

## 用户修改保护

修改标题或排期即手动接管；备注、优先级和标签仍可跟随。已完成待办不会被来源刷新重开。取消订阅选择保留时转为基础待办；删除仅允许未完成记录。直接删除关联待办会停止跟随，后续刷新不会复活。

恢复跟随会应用当前来源标题及排期，需要先读取最新来源和待办修订。修订冲突后应重新核对。分类隐藏不会取消订阅；主动隐藏后新订阅也不会覆盖偏好。

## 来源刷新

日历操作区和工具页面可以请求刷新。按钮提交后立即返回排队状态，只有成功导入后才更新「最近成功」；重复点击会复用同一来源的有效请求。

HTTPS JSON 来源由正在运行的 App 或 MCP 拉取并按工具配置映射，无须新增专用宿主命令。App/MCP 均未运行时不会同步；重新运行后最多补一次到期刷新。来源失败、空响应和无效批次不会清空已有事件，状态会保留错误供重试。停用工具、来源或撤权后，旧请求不能继续提交。

需要外部助手核验的标准导入来源显示「等待外部助手核验并导入」。这只创建更新请求，不会自动运行 AI；外部助手提交有效标准事件后才完成请求。使用这类工具时，需让已连接 Dayfolio 的助手查看来源状态并完成导入。

日历「显示内容」面板只控制显示，隐藏分类不会取消订阅或删除待办。
