## 这是什么

TodoDesk 的学习闭环以 **AI agent 为第一操作者**：你在 zcode 等 AI 客户端里说「学习线性代数」，agent 按 TodoDesk 规范完成从计划到沉淀的全流程；App 内只做**展示与确认**（草案确认、调整应用、卡片导出），没有手工建计划的表单。

App「学习计划」首页默认显示**计划**，标题右侧可切换到**课程**。计划卡显示关联课程；暂未关联时显示「待关联课程」。计划可先排期，但最终应关联课程：请 agent 导入课程样课并引用现有计划，或为未绑定课程重导同内容样课包补上计划关联。

打开计划后，点击每日条目的文字或「详情 →」可进入**计划条目详情**，查看完整安排、日期、类型、预计时长、当前状态，以及与该条目关联的学习会话和测评；有知识点掌握数据时也会显示。条目左侧的勾选按钮可直接完成或撤销完成，待办条目仍可直接「跳过」。详情页也能完成、撤销、跳过或恢复待办；返回计划详情时保留原来的浏览位置。打卡状态与知识点掌握度分别计算，完成条目不等于通过测评。

本文件是学习闭环的**唯一规范源**：MCP 的 `get_study_workflow` 工具与 `tododesk://study/workflow` 资源返回的就是本文内容（构建时同源注入），改规范只改这里。

## 全流程（agent 操作规范）

1. **澄清目标**：缺信息先问用户，不要编造。需要澄清的典型项：学习动机与目标水平、每日时间预算（分钟）、材料来源（书/课/文档）、起点与先修基础、期望完成时间。
2. **先修诊断**：按目标拆知识点时先判断用户是否具备先修知识；不确定就单独拆成前置知识点放进计划，或先问一句。
3. **生成草案（有日期）**：用户已给出起始日期与每日预算时，调用 `draft_study_plan`，传入标题、目标、材料来源、每日预算（10~600 分钟）、开始日期与知识点清单（每项含稳定 `key`、名称、依赖 `depends_on`、预计时长、可验证成果 `outcome`）。TodoDesk 按**透明规则**（见下）排成逐日安排并保存为**草案**——此时不创建任何计划、待办或打卡。缺失的时长/成果会记录在草案的 `assumptions` 里，向用户展示，不要默默补造。
4. **无日期先存（日期待排期）**：用户**尚未**给出起始日期与每日预算（如「这批专题文稿先存着，什么时候学再定」）时，调用 `draft_study_topic` 保存**无日期专题草案**：只存主题大纲/知识点/材料与可选的样课课程关联（`course_id`，样课未确认也可关联）——**不排日程、不产待办、不占每日预算**。知识点在创建时即校验（key 格式/依赖/环），内容可随后用 `update_study_topic_draft` 更新（仅未排期时）。**不要**为了走 dated 流程替用户拍日期或预算。
5. **排期（预览 → 确认提交）**：用户给出起始日期与每日预算后，先调 `preview_study_draft_schedule` **只读预览**——逐日安排、依赖拓扑顺序、与其他**进行中计划**的每日预算冲突（既有占用 + 新排超预算的日子，汇总在返回的 `over_budget_dates`）与知识点重复预警、透明规则假设；**有预警必须逐条念给用户**。用户明确同意后才调 `schedule_study_draft`，并把 `over_budget_dates` **原样**作为 `confirmed_over_dates` 传回——服务端在**事务内按当下库状态重算并硬校验**：有冲突未确认、预览后既有计划变动导致冲突集变化、冲突已消失却仍带旧确认集，一律拒绝（UI 提示不能替代服务层校验）。同参数重复提交**幂等**；未确认前换参数 = 重新排期（重新过硬校验）。
6. **预览与确认**：把草案逐日安排与假设念给用户；用户同意后调用 `confirm_study_plan_draft`（生成正式计划与逐日待办，幂等可重试）。**确认边界同样硬校验冲突**（经 `schedule_study_draft` 排期的草案）：排期之后、确认之前既有计划可能变动——确认时服务端重算超预算日期，存在冲突必须再次携带与重算**精确一致**的 `confirmed_over_dates`，否则拒绝（建计划期间的并发变动由复检兜底，不一致整体回退，不留冲突未确认的计划）。用户不要就 `cancel_study_plan_draft`（无任何副作用）。未排期的草案不能确认（会拒绝并提示先排期）；旧路径草案（`draft_study_plan` 创建即排期）确认不设冲突门（历史行为保持）。
7. **每日执行**：每天从 `get_today` 看当日安排。学习完成后调用 `record_study_session` 记录一次独立会话：实际用时、**自己的解释/答案**（用自己的话讲出来）、疑问、材料来源。同一目标学了几遍就记几条（`attempt` 递增），重试请带同一稳定 `id` 保证幂等。
8. **测评留证**：调用 `record_study_assessment` 记录题目、评价标准、原答案、评分与**依据**。`source` 必须显式：`self`（自评，可被后续纠正）、`objective`（客观测试，**必须附真实判题依据 evidence 与判题结果**，TodoDesk 不代判也不伪造）、`ai_suggestion`（AI 的建议性反馈，仅记录，**不计入掌握证据**）。
9. **复盘调整**：周期性调用 `suggest_plan_adjustments` 获取建议（纯预览、不写库），依据来自漏做条目与薄弱证据；用户确认后 `apply_plan_adjustments`（入参携带预览时的建议日期做**快照绑定**——计划已变化导致建议日期不同则拒绝该条并要求重新预览；只动**未完成**条目，同步关联待办截止日，必要时延长计划）。用户不确认就不调用——取消永远无副作用。
10. **知识沉淀**：学习稳定后调用 `preview_study_cards` 预览待审卡片；用户确认导出目录后 `export_study_cards` 写出 Obsidian Markdown（`status: draft`、`verified: false`，含来源、会话 ID、测评证据）。同一卡片重复导出幂等，**被人工编辑过的文件永不覆盖**。导出目录必须是用户指定的独立目录——core 层会**硬拒绝**写入任何知识库 vault（含已注册 vault、内置默认保护根 `~/Desktop/knowledge-base` 即使尚未注册、`TODODESK_PROTECTED_DIRS` 指定目录；符号链接别名同样拦截），而不是仅靠提示。

## 透明规则（可验证的不变式）

- **排程**：知识点先按依赖拓扑排序（保持输入顺序，有环报错），再从开始日按每日预算装箱；单个知识点超过全天预算时单独占一天并记入假设。
- **无日期草案零副作用**：`draft_study_topic` 只写草案表（start/end/daily_minutes 为空、items 为空）——不排日程、不产待办、不占预算、不进今日面板；创建时即校验知识点（key 格式/去重/依赖存在性/环检测）。
- **排期两段式（冲突硬校验，服务层强制）**：`preview_study_draft_schedule` 纯只读——逐日安排 + 依赖拓扑顺序 + 与进行中计划的**每日预算冲突**（其他 active 计划当日既有占用 + 本草案新排超出声明的每日预算，汇总为 `over_budget_dates`）与**知识点重复**（同 key 已在其他 active 计划未完成条目里）预警；`schedule_study_draft` 在 **BEGIN IMMEDIATE 事务内重算**超预算日期并与 `confirmed_over_dates` **精确匹配**（集合完全一致才放行——有冲突未确认、确认集过期、冲突消失仍带旧集均拒绝），事务落库且**同参数重复提交幂等**，未确认前换参数 = 重新排期（重新过硬校验）；已确认/已取消的草案拒绝排期；未排期草案不能确认。**确认边界重检**：确认时按当下库状态再算一次（建计划后还复检一次以捕获并发写入，不一致整体回退删计划删待办）；旧路径草案（`draft_study_plan` 创建即排期，无排期提交时刻标记）确认不设冲突门——豁免仅限这一类，不削弱新排期草案的任何校验。
- **调整建议依赖感知**：漏做条目改期后，若其**未完成后继**条目会早于前置（含改期后的生效日期），预览会**联动顺延后继**到前置之后的预算空位，绝不让后继排在未完成前置之前；已完成/已跳过的前置视为已满足，不再约束后继；级联逐日传播并逐条预占每日预算。
- **依赖组完整性（部分应用保护）**：应用时只勾选前置改期而落下其后继的联动建议，会被**整组拒绝**（该条跳过并说明需一起勾选的建议）——落库计划任何时刻都不会出现「后继早于未完成前置」；传递链（A→B→C 只勾部分）按不动点逐级回退。
- **掌握度判定**（`get_mastery`，只看测评证据，与任务完成率分开展示；**证据按计划隔离**——只统计归属该计划的测评，传 `plan_id` 或关联会话即可归属）：

| 判定 | 条件 |
| --- | --- |
| unknown | 计划内尚无 self/objective 测评（打卡、会话都不算掌握） |
| strong | 存在客观测评：最新客观判题通过；无客观测评：最新自评 ≥ 80 |
| reviewing | 无客观测评，最新自评 60~79 |
| weak | 存在客观测评：最新客观判题未通过；无客观测评：最新自评 < 60 |

- **客观优先**：只要存在客观测评，判定只看最新客观结果，较新的自评不覆盖客观；`ai_suggestion` 不参与判定。
- **可纠正**：同一测评 id 重新提交会保留 `corrections` 历史（旧评分不丢失）。
- **幂等**：会话按稳定 id 或（目标, attempt）复用；草案确认一次（重复确认返回原计划）；排期同参数重复提交返回原排期；卡片按内容哈希去重。
- **调整边界**：`apply` 瞬间已不是 pending 的条目自动跳过；已完成条目与历史会话永不被改写。
- **缺省值**：知识点时长缺省 60 分钟；旧计划无预算时调整按 120 分钟/天估容量；自动补复习条目 20 分钟。

## 工具对照

| 阶段 | MCP 工具 | 读写 |
| --- | --- | --- |
| 规范 | `get_study_workflow` / 资源 `tododesk://study/workflow` | 读 |
| 草案（有日期） | `draft_study_plan`、`list_study_drafts`、`get_study_draft` | 写（仅草案表）/读 |
| 草案（无日期） | `draft_study_topic`、`update_study_topic_draft` | 写（仅草案表，零副作用） |
| 排期 | `preview_study_draft_schedule`（只读预览：冲突+依赖）、`schedule_study_draft`（事务+幂等） | 预览/写 |
| 确认 | `confirm_study_plan_draft`、`cancel_study_plan_draft` | 写（幂等/无副作用） |
| 会话 | `record_study_session`、`list_study_sessions` | 写（幂等）/读 |
| 测评 | `record_study_assessment`、`list_study_assessments`、`get_mastery` | 写（留证）/读 |
| 调整 | `suggest_plan_adjustments`、`apply_plan_adjustments` | 预览/写 |
| 卡片 | `preview_study_cards`、`export_study_cards`、`list_card_exports` | 预览/写文件 |

计划条目本体（`study_plan`/`plan_item`）、打卡与待办沿用既有工具（`create_study_plan`、`update_plan_item`、`get_today` 等）。草案确认生成的计划与普通计划完全同构，App「学习计划」面板与 `get_today` 直接可见。

## 卡片格式

导出的每张卡片对应**一次真实会话**，文件名 `TD-<知识点>-<完整会话id>.md`（会话 id 即主键，文件名天然不碰撞）。frontmatter 声明 `source`（TodoDesk 学习会话）、`session_id`、`knowledge_key`、`status: draft`、`verified: false`、`assessed`（测评证据摘要或 none）；正文是学习者当时的自述（我的解释/疑问/测评证据/材料），并带「待审卡片」警示：**内容未经核实，不代表主人观点，也不代表已掌握**。请人工审阅后再整理进知识库。
