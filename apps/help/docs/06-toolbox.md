## 工具列表

工具箱统一收纳 HTML 页面。顶部显示工具数量、「管理分类」和「导入 HTML」。工具按分类排列，卡片左侧为图标、右侧为名称，点击即可在应用内打开；顶部「工具箱」返回列表。

每个工具只有导入和删除操作，不提供编辑、启停、卸载、版本或回滚入口，也不接受运行时工具包安装。工具自带的筛选、资料展示等页面功能由其 HTML 决定。

## 导入 HTML

1. 点右上角「导入 HTML」。
2. 选择一个 `.html` 或 `.htm` 页面，可同时选择相对路径引用的 CSS、JS 和图片。自包含页面只需一个 HTML 文件。
3. 核对名称，选择图标与分类，不选分类则归入「未分类」。
4. 点「导入」，成功后卡片出现在列表中。

无需 manifest、安装包或工具版本。HTML 页面可以展示随文件保存的数据；接入待办接口的页面还可以请求添加事项。导入不会自动创建待办、登记事件订阅或启动后台刷新。

## 从工具添加待办

接入此能力的页面会提供「加入待办」等按钮。点击后由 Dayfolio 显示「添加到待办」预览，核对标题与时间，点击右下角确认才会写入；取消或关闭预览不创建待办。

批量添加可逐条勾选或全选，已添加、已完成及已移除的事项会标明并跳过。每批最多 100 条。重复添加同一来源事项会复用已有待办，不覆盖你修改的标题、时间、备注或完成状态；删除过的事项不会因再次批量添加自动恢复。删除工具仍保留个人待办。

预览同时显示「待办分类」。未声明分类的 HTML 默认按工具名称归类；页面也可按内容声明分类名称与颜色。第一次确认并实际添加新待办时，App 在同一事务中创建或复用分类；取消预览、全部事项已存在或添加失败，都不产生空分类。同一工具的相同分类键会复用原分类，不覆盖既有名称、颜色或日历隐藏偏好。

添加后可在「待办」顶部按分类筛选，行内显示分类名称；日历更多菜单的「管理分类」中可单独显示或隐藏该分类。隐藏只影响日历展示，待办列表和完成记录仍保留。删除工具不会删除分类或个人待办。

欧冠赛事页支持单场「加入待办」和球队详情的「批量加入待办」，批量仅包含页面当前已知、尚未开赛的未来比赛。球队的「加入筛选」与比赛收藏只用于本页筛选；「持续关注」是单独确认的功能。

「加入待办」和「批量加入待办」是一次性保存当前内容。需要同步后续变化时选择下述持续关注。已知开球时间按共享显示时区显示；只知道开始时刻时不补填结束，未知时间的事项不排期。

## 持续关注

接入此能力的 HTML 工具可持续关注单项或分组。欧冠页在比赛旁点「持续关注」，在球队详情点「持续关注赛程」；先核对宿主弹窗中的范围、分类与已有待办，再确认。取消预览不保存规则、待办或空分类。没有未来事项的分组也可确认关注，实际出现新事项后再创建分类与待办。

资料由页面或助手核实并发布后，宿主自动同步已确认关注：改期更新仍在跟随的待办，分组新增的未来或时间待定事项自动加入，单场与多个分组重叠不重复创建。更新 HTML 完整文件集中的 `dayfolio-follow.json` 时，页面关闭也生效。持续关注不会自行联网抓取赛程；来源更新时间应以实际核实和发布结果为准，缺少条目不视为取消。

自动同步只更新标题与排期；备注、标签、优先级和分类偏好保留。手动修改标题或时间后转为个人安排，不再自动覆盖；已完成记录原样保护，不自动重开；已删除记录不自动恢复。取消或时间待定的来源不编造时长，也不自动删除或完成待办。

已有比赛待办可点「已添加 · 详情」或「已完成 · 详情」；「待办」中的工具事项也有「来源详情」，日历可打开同一详情。详情展示最新来源与保护状态，可停止关注并保留待办，或核对最新标题、时间后明确恢复跟随。恢复会校验来源和待办修订，不覆盖操作期间发生的修改，已完成记录继续受保护。

取消分组关注保留已有待办，其他仍有效的关注规则继续生效；取消单项后，分组更新不会重新启用它。删除分类停止该分类的持续关注，删除工具停止其全部关注，两者均保留个人待办。页面筛选、收藏与真实关注分别保存。

### 给 HTML 接入按钮

Dayfolio 打开工具时提供 `window.dayfolio`，页面声明的 CSP 需要允许同源脚本。页面只获得添加待办及查询本工具关联状态的能力，创建仍由 App 预览确认；不访问数据库或原始 IPC。独立浏览器或旧版 App 没有此接口时，页面应显示无法连接待办并保留其他功能。

```js
await window.dayfolio.ready;
await window.dayfolio.todos.create({
  sourceKey: 'uefa:2026-27:比赛唯一ID',
  title: '观看欧冠比赛',
  startAt: '2026-11-04T04:00:00+08:00',
  sourceUrl: 'https://example.com/match'
});
```

`createMany(items)` 批量请求；`getStatus(sourceKeys)` 查询 `missing / open / done / deleted` 状态。两者每批最多 100 条；单次页面消息最多 64 KiB。每个草稿必须有 `sourceKey` 与 `title`，可带 `notes`、`priority`、`tags`、`sourceUrl`。`sourceKey` 在工具内稳定唯一，修改内容、改期或从单场改为球队批量时保持不变。相同键只在同一个工具内去重。

单项和批量创建均可传第二个参数，例如 `createMany(items, {category: {key: 'reading', title: '读书会', color: 'green'}})`。分类键以字母或数字开头，只含字母、数字、点、下划线或连字符，最长 80 字符；名称最长 80 字符，颜色支持 `blue / green / violet / amber / rose / slate`。分类身份按工具隔离，相同名称不会自动合并其他工具的分类；不能指定宿主分类 ID。省略参数时沿用工具的默认分类。对已存在或已移除事项重复添加，不迁移旧待办的归属。

固定时刻用带 Z 或偏移的 `startAt`，已知结束时刻可加 `endAt`；只知道日期则用 `dueDate`（YYYY-MM-DD），不和固定时刻混用。无日期时全部省略。成功返回 `{created, reused, deleted, items, category}`，`category` 返回实际存在的分类或 null；取消抛出 `USER_CANCELLED`，页面应展示实际结果。

## 删除工具

鼠标悬停或键盘聚焦卡片后，点击右上角垃圾桶。确认后删除登记信息与全部 HTML 及配套文件，不可恢复。删除工具不会删除独立保存的待办、学习或订阅历史。

## 让 AI 代劳

接入 MCP 的 AI 客户端可通过 `list_tools` 查找工具、`add_tool` 导入 HTML、`delete_tool` 删除指定工具。已有 HTML 内容的维护仍可通过 `update_tool` 整体替换文件，App 不另设编辑和版本管理界面。

将页面事项加入待办时，助手先用 `preview_tool_todos` 核对内容，再按用户要求调用 `add_tool_todos`；`get_tool_todo_status` 查询关联状态，三者与 App 共用服务。

- 「把 ~/Downloads/色板.html 加到工具箱」。
- 「帮我写个倒计时小工具放进工具箱」。
- 分类不存在时 AI 会自动创建；App 与 MCP 共用同一套登记和文件服务。

## 分类管理

「管理分类」中可新增、重命名、排序和删除分类。删除分类只把其中工具移入「未分类」，不会删除工具。

## 数据存放

登记信息保存在应用数据库，HTML 及配套文件保存在数据库旁的 `tools/<工具id>/` 目录。默认位置为 `~/Library/Application Support/tododesk/tools/`。

App 与 MCP 共用文件写入服务，导入先暂存、失败恢复原目录。页面或文件存在不代表已验证其实际功能；具体功能需打开工具核对。

待办分类可在日历的更多菜单 →「管理分类」中显示或隐藏、编辑名称与颜色、确认删除。删除自定义分类会保留已有待办并转入基础待办，工具去重关联仍保留；再次确认添加新的事项时可以重新创建分类。工具箱的分组与待办分类分别管理。
