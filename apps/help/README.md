# @tododesk/help —— TodoDesk 帮助中心

App「帮助」面板（侧边栏底部 → 帮助）展示的全部内容来自本目录。这是一个**独立维护的文档子项目**：`docs/` 下一个 markdown 文件对应一个模块的使用说明，构建时同步进桌面端渲染层。

## 目录结构

```
apps/help/
├── docs/                 # 模块使用说明（文件名前缀决定目录顺序）
│   ├── 01-today.md       # 今日
│   ├── 02-todos.md       # 待办
│   ├── 03-plans.md       # 学习计划
│   ├── 04-checkins.md    # 打卡
│   ├── 05-news.md        # 新闻
│   ├── 06-toolbox.md     # 工具箱
│   ├── 07-tray.md        # 菜单栏与快速捕获
│   ├── 08-mcp.md         # MCP 与 AI 接入
│   └── 10-data.md        # 数据面板与本体
├── scripts/sync.mjs      # 同步脚本：docs → 渲染层生成文件
└── package.json
```

## 工作流（重要）

**修改功能或新增功能后，必须同步更新本目录**（约束写在仓库根 `AGENTS.md`）：

1. 改了哪个模块，就更新对应 `NN-<模块>.md`；新增了模块/面板，新建一个带序号前缀的 md；
2. 运行 `npm run help:sync`（monorepo 根目录），生成 `apps/desktop/src/renderer/src/generated/helpContent.ts`；
3. 生成文件**禁止手改**，随源码一起提交；
4. 涉及新入口/交互的，顺手核对其余文档中对入口的描述是否仍然准确。

`npm run build:web` 会自动先跑一次同步；`npm run dev` 启动时同步并监听 `docs/` 变更热更。

## 文档格式

每个文件以 frontmatter 开头：

```markdown
---
title: 模块名
description: 一句话说明（显示在帮助目录里）
---

正文……
```

正文支持一个克制的 markdown 子集（帮助面板内置渲染器，不引第三方依赖）：

- 标题：`##` / `###` / `####`（`#` 留给面板自身的文档标题）
- 段落、`**粗体**`、`` `行内代码` ``、`[链接](url)`
- 无序 / 有序列表（支持 2 空格缩进一级嵌套）
- 围栏代码块、`>` 引用、`---` 分隔线
- 管道表格（首行表头 + `---` 分隔行）

写作约定：面向使用者、动作导向；写实不写愿景——功能改了文档必须跟着改，这是本子项目存在的意义。
