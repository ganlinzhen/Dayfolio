# 参赛队伍资料：队标、介绍与本届名单

生成团队赛事页面时读取本参考；个人、组合和代表团赛事按其主体调整，不把战队字段机械套给所有项目。

## 先获取真实资料

- 每支队伍都要有真实队标与简短介绍。先从本届官方参赛页、联盟或俱乐部官方页查找队标，核对队伍身份、更名与当前届次。下载到工具资源目录并记录原始 URL、发布页、版权与获取时间，逐个检查图片能解码、主体可见；不要只给前三支队伍配图。
- 页面中队标用于赛程、队伍目录、详情与晋级图，同一实体复用同一资源。保留完整比例，不拉伸或用错误背景吞掉黑色/白色队标。未知席位使用「待定」符号，已知队伍不能长期用队名首字母、文字方块或自制假队徽代替真实队标。
- 介绍至少回答「这是谁、与本届赛事有什么关系」。优先核实所属地区/联盟、俱乐部背景、本届资格/种子与已发生的赛事经历；可补充有来源的历史背景。用自己的中文简要概述，不能只有全称、赛区和一个空详情按钮，也不编造打法、荣誉或精确评分。
- 人员名单必须实际检索：先找本届官方报名/参赛名册，其次当届俱乐部公告与联盟页，必要时用可靠赛事报道交叉核对。按队保存选手、位置/职责、主力/替补、名单适用届次、来源、真实发布日期或未知、核实时间。名单有来源就填入详情，不把「待核实」和更新提示词当作完成了资料收集。
- 当前俱乐部名单不自动等于历史赛事名单。区分注册名单、报道中的预期五人组与已经实际出场的阵容；临时替补、签证变化与来源冲突单独注明，不把旧名单静默混成一支从未存在的队伍。无法确认部分可保留未知，说明已查范围和具体缺口。

## 人员中文名、头像与详情

- 页面一旦展示球员或电竞选手，就同时提供中文译名、来源原名或游戏 ID、头像位和可点击的个人详情入口；不能只有英文姓名、不可点击的头像或空详情按钮。中文名优先使用官方中文资料，其次使用可追溯的通行译名；自行音译必须标注「中文音译」，不能冒充官方姓名。电竞保留游戏 ID，不把外号、游戏 ID 的字面翻译或音译写成真实姓名；只有可靠来源确认后才展示中文本名。
- 保留 ESPN 等提供方的球员稳定 ID，以提供方命名空间关联资料与图片；同名、重音符号、姓名顺序及电竞改名要核对身份，不能只靠模糊姓名自动配图。增量补充个人资料不能替换已有名单成员、号码、历史队属或人工注释，也不重置 pageId、toolId、关注、收藏和本地偏好键。
- **头像优先使用官方定妆照**：依次查找本届赛事/联盟官方球员页（如 UEFA、英超官网、LoL Esports）、俱乐部官方球员页的正面或半身定妆照，再考虑可靠数据提供方明确标识的人物头像。普通比赛现场照、新闻配图、合影与全身照不作为默认头像；不能为了填满头像位，把图库中任意一张人物照片当作定妆照。仅取得资料照时单独标注其类型和缺口，不计入官方定妆照覆盖。
- **头像框按已获取图片的平均尺寸决定**：对当前页面实际使用、可解码的头像逐一读取宽高，同一人物资源去重，排除缺图和解码失败的样本；以「平均宽 ÷ 平均高」确定该页统一展示比例，保存样本数、平均宽高及比例。每个赛事按自己的图片样本计算，不再固定为正方形或略竖框。名单、伤停条目和详情复用同一图片及比例，按所在位置缩放。
- **图片铺满头像框，特殊尺寸拉伸铺满**：常规图片用 `object-fit: cover`，居中并优先保留头部；相对平均宽高比偏离较大的图片用 `object-fit: fill`，允许按用户要求非等比拉伸。实现时记录判定阈值（例如相对偏差超过 8%），不要继续用 `contain` 造成上下或左右留边，也不要通过额外裁图删除头部来伪装铺满。明确设置图片的宽高、块级展示及最大尺寸，防止页面通用 `img` 样式覆盖；透明图可去除透明留白，背景与页面一致。保留原图与来源，拉伸只是展示策略，不重绘人物。缺图占位使用同一尺寸，不能挤压姓名或撑高名单行；桌面与窄屏实际截图检查普通图、特殊比例图、缺图及详情，确认无外部留白或布局跳动。
- 图片下载到工具内，记录原始 URL、发布页、归属、照片类型、适用届次、核实时间与未知的发布时间 `null`，逐张验证可解码与人物身份。旧赛季定妆照注明年份，照片中的队服不能作为本届注册证据。禁止生成假人像、冒用同名人物或以队标冒充头像；未取得可靠定妆照时显示中性人物占位和「暂无可靠定妆照」，在覆盖报告中列出缺口。
- 点击姓名、头像或整个人员卡片打开详情，并提供关闭或返回与键盘操作。详情至少展示中文名、原名/游戏 ID、本届关联队伍、位置/职责、现有号码与名单状态、届次、资料来源及核实时间；出生日期、国籍、身高等仅展示已取得的字段，缺失明确标注，不凭年龄倒推出生日期，不编造履历、评分或荣誉。已确认伤停、正式首发、首发预测与分析分别展示，个人基本资料不自动构成出场确认。
- 中文名与头像在球队名单、伤停条目、首发/预测名单中复用同一人物资料；无法确认稳定 ID 的人员保留来源姓名和身份缺口，不能为了打开详情而虚造 ID。头像应有可访问名称、按样本确定的统一比例和加载失败回退；手机端姓名可换行、头像框不能被布局挤压，特殊尺寸按上述策略拉伸，长中文译名不能挤坏比分和球队布局。

## 页面与配置

队伍目录应显示队标、名称、赛区和一段介绍；点击后展示完整简介、已获取的本届名单、参赛状态、关联赛程及资料来源。手机端不能把名单挤成不可读的五列。

可在 `participant` 记录的 `data` 中保存 `logo`、`introduction`、`profileReferences`、`roster` 和 `rosterNote`，或者使用关联的独立人物记录。`logo` 记录包内路径、来源和归属；`roster` 每人保留稳定 ID、游戏名/姓名、位置、状态和来源引用。个人资料可用 `nameZh`、`nameOriginal`、`nameZhKind`、`portrait`、`profile` 与逐字段来源保存，避免只写入无法回读的 HTML。来源页按实际范围区分官方图片和第三方报道名单，不能把所有数据都标成官方。

## 验收

- 统计真实参赛队伍数、有效队标数、非空介绍数、已取得名单的队伍数和剩余缺口，输出覆盖结果；不能仅核对文件数量。
- 浏览器实际加载所有队标，在深浅底、紧凑赛程与晋级卡片中检查辨识度；抽查不同赛区和长队名详情，至少核对五个位置、替补与来源状态。
- 内容校验要识别重复选手、错队、跨届、位置遗漏与未解决冲突；没有足够证据时降低确定性而不猜测。
- 单独统计人员总数、中文名覆盖、官方定妆照覆盖、其他可靠人物头像覆盖、资料照与占位数、可用详情入口数，以及头像尺寸样本、平均宽高、展示比例和特殊尺寸数；不能把现场照或资料照算作官方定妆照。抽查中文长名、同名人员、电竞游戏 ID、缺图和键盘返回。在桌面及手机宽度实际点击头像和姓名，确认普通图片铺满、特殊尺寸确实拉伸铺满、头部可见、详情属于同一稳定 ID，关闭后保留筛选和个人偏好；读取更新后的完整文件集核对数据与页面一致。
