# Dayfolio 教学

本参考让 agent 按 **Dayfolio 学习闭环规范**（`get_study_workflow` 工具返回的单一来源）执行教学。
调用方式：**显式**（用户明确要求学习某主题时）——不自动触发、不冒称已自动调用。

## 执行流程（透明规则见 get_study_workflow 返回的规范全文）

1. **澄清目标**：问用户学习动机、每日时间预算（分钟）、材料来源、先修基础——缺信息不编造。
2. **生成计划草案**：`draft_study_plan`（知识点分解 + 依赖 + 每日预算）；把逐日安排与假设展示给用户。
3. **确认**：用户同意 → `confirm_study_plan_draft`；拒绝 → `cancel_study_plan_draft`（无副作用）。
4. **课程内容**（教学插件扩展）：
   - **任何课程包必须恰好含一个 `is_sample` 标记**（样课包仅样课一天；完整包保留样课标记）——
     无标记包会被拒绝；首次导入完整包同样被拒绝，用 `import_course` 导入样课；
     **plan_id 绑定后不可改绑**（重导省略 plan_id 表示沿用原绑定）；
   - 用户先在 App **阅读样课**，再在对话中明确确认；agent 用 `get_course_lessons` 核对课程及样课 `content_hash`，收到针对当前版本的明确同意后调用 `confirm_course_sample`（`confirmed: true`、`sample_content_hash`），无需用户回 App 点击按钮。只确认样课时仅记录确认；用户同时说「继续生成完整版」时，立即继续 `create_course_request` 及下述认领、生成、导入流程，不让用户重复点击或重复授权；
   - agent 定期 `list_course_requests` 发现 pending → `claim_course_request` 认领 → 编写完整包（含样课天且**样课正文与已确认版本逐字节一致**，否则导入即拒）→
     `import_course` 导入（仅认领后放行）→ `complete_course_request` 完成（核验确认哈希未过期 + 天数覆盖绑定计划的全部天数，缺一天即拒绝；绑定计划被删除亦拒绝）；
   - **逐课版本**由服务自动维护：新课从 `revision: 1` 开始，正文或教学资料实际更新才递增；App 显示 v1、v2，`import_course` / `get_course_lessons` 返回 revision。不要在课程包手写课次修订号，也不要把课程包 version 当作每课版本；相同内容重复导入与阅读答题不递增；
   - **内容生成不算掌握**：掌握证据只来自 `record_study_assessment`（自评可纠正/客观须带判题依据）。
5. **每日执行**：`record_study_session`（自己的解释、疑问、材料；实际用时可省略，仅用户主动提供时记录）。
6. **测评**：`record_study_assessment`（source 显式：self/objective/ai_suggestion）。
7. **复习调整**：`suggest_plan_adjustments` 预览 → 用户确认 → `apply_plan_adjustments`。
8. **沉淀**：`preview_study_cards` → 用户指定目录 → `export_study_cards`（status: draft, verified: false）。

## 入门课程的正文与配图规范

生成或修订讲义时执行本节；用户只查询进度时不生成内容。入门课要让学习者不跳转源码也能完成主要学习任务。

- **以当前实现为依据**：先核对当前源码、接口或可靠材料，记录核对版本。正文直接讲当前有效的行为、操作与设计原因；删除旧版本对比、迁移史、失效功能及无教学价值的“没有 xxxx / 旧的 xxx”。只保留会影响当前操作的必要限制、环境前提和安全边界。纠错过程写在交付说明，不写进讲义。
- **代码直接讲清楚**：围绕一个小而完整的任务，正文展示少量核心方法或精简代码，逐段说明输入、处理、输出、为何这样设计。摘录保持语法完整，明确标注省略范围；教学模拟与生产实现分别标注。提供具体输入/输出或请求/响应示例，注明运行前提，未实测的示例不能写成实测结果。源码参考集中到文末作为少量可选深入阅读，不用路径列表代替讲解。
- **图用来解释关系**：优先用流程图讲步骤与分支，用结构图讲职责与边界，必要时用时序图或数据流图讲交互。每张图明确要帮助理解哪个问题；箭头、节点和正文语义一致，不为数量堆装饰图。复杂图拆成可读的小图。
- **匹配真实渲染能力**：核对当前 App 的 HTML 消毒与 CSP。当前讲义采用静态内联 SVG 或兼容 HTML/CSS；Mermaid 等需预渲染为内联静态图。不得依赖运行时脚本、CDN、外部图片或被 CSP 禁止的资源。SVG 提供 viewBox、标题/文字说明，使用可辨字号、对比度和明确连线；检查阅读面板及窄视口下的布局、文字截断与箭头方向。
- **导入后检查代码文本**：HTML 中的代码必须转义；对可能被消毒规则误识别的文本采用适当实体编码，例如等号写为 `&#61;` 后显示仍为 `=`。通过正式读取接口回读，解码代码块并与预期文本核对；不能以源文件正确代替 App 中显示正确。

### 可执行验收清单

1. 对照当前源码或材料，核对主要方法、输入/输出、默认规则及错误分支，区分事实与教学简化。
2. 只读正文能否完成学习目标？核心代码是否完整可读，说明是否覆盖输入、处理、输出与设计原因？文末引用是否确为可选？
3. 每张图是否解决一个明确问题，节点与连线是否与代码一致？检查静态资源、字号、窄视口和实际 App 显示。
4. 搜索“旧版、以前、已废弃、没有”等表达，逐项删除历史包袱，仅保留影响当前操作的真实边界；不机械删除必要的否定条件。
5. 隔离验证导入与消毒；正式导入后回读正文、代码和图表。App 验收若受阻，明确报告未验收项，不能声称显示已通过。
6. 更新已有课程先通过公开接口备份身份、确认状态、逐课已读与答题，并保存原资产；保留 slug 和原 plan_id。正文变更可能重置对应课次已读/答题并使样课确认过期，先核对实际导入语义与授权；只更新获准课次，不代确认，不把生成内容写成掌握证据。样课确认、版本与完整包绑定仍遵守原流程。

### 正反例

- 反例：“打开 A.ts、B.ts、C.ts 自己追调用；旧版曾支持 X，现在没有 X。”
- 正例：“图示请求 → 参数校验 → 核心方法 → 返回；正文给出完整方法和输入/输出例子，解释默认值与失败出口；文末列两个可选源码入口。”
- 反例：代码从半个括号开始，省略后改变语义；放入 Mermaid 文本和 CDN script，未看 App 就声称图表正常。
- 正例：保留完整语句并标注节选，图预渲染为内联 SVG，导入后核对代码文本并检查实际布局；真实限制写成“此实验使用内存替身，只验证解析规则”。

## 安全边界

- 绝不读写用户真实 SQLite 库（测试用 `TODODESK_DB=<临时路径>` + 独立 `HOME`）；
- 讲义 HTML 会被消毒（script/事件/危险协议剥除，外部资源 http/https 一律中和，讲义须离线自包含）；
  讲义引用的包内 .css 样式表会在导入时内联为离线 `<style>`（@import 与外部 url() 移除，课程排版保留）；
  源码导读是纯文本，不执行命令；课程包拒绝路径穿越与符号链接（symlink）；
- 样课确认须来自用户对当前内容的明确同意，可在对话中表达；已读、已导入或旧版本的同意不等于本次确认。样课变更后须重新阅读并确认；通用本体动作不能绕过专用工具；
- 导入失败不留孤儿（资产先就位、库后写入），样课包重导不删除其他已生成课次；内容哈希不变的课次保留已读与答题，正文变化的课次会重置相应记录，样课变化还会使确认过期。
