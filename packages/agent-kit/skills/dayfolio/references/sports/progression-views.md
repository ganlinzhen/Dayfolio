# 阶段进程与晋级图

每个阶段先选择适合它的进程图，尽量呈现参赛者如何流向下一轮。用户给出对阵图参考时，复用它的比赛卡、轮次列、队标、胜负强调和连线表达；不能用普通结果列表宣称已生成晋级图。

| 阶段赛制 | 推荐进程视图 | 需要区分 |
| --- | --- | --- |
| 单败淘汰 | 轮次列与连线组成的对阵树 | 胜者去向、待抽签席位、决赛与冠军 |
| 双败淘汰 | 胜者组、败者组及资格赛/决赛的流转图 | 胜者晋级与落败转入败者组，不省略复活路径 |
| 瑞士轮 | 按轮次和战绩分支的状态图 | 获胜/落败去向，三胜晋级/三负淘汰；抽签前没有确定对手 |
| 小组/循环赛 | 分组排名与晋级区连接至下一阶段 | 同分规则、跨组名额与未定席位 |
| 多轮成绩赛 | 预赛、复赛、决赛成绩与晋级线 | 成绩规则与实际通过者 |

## 用数据表达流转

- 比赛卡包含阶段/轮次、日期时间、局制、双方真实标识与比分。结束后胜方有文字/图形与颜色强调，败方降低强调但仍可读，不能仅凭颜色识别输赢。
- 节点引用稳定比赛/实体 ID，连线记录来源、目的、`winner` / `loser` / `qualification` 等关系。已确认路线和规则允许的条件路线用不同线型并给图例；连线接到卡片边缘，避免穿过文字。
- 双败图必须能追踪首轮败者进入败者组、败者组胜者继续、胜者组落败方再入败者组，以及最终资格赛/决赛。不要只画胜者组的单败树。
- 瑞士轮可绘制 0-0 → 1-0 / 0-1 → 后续战绩分支，标注每个分支的胜负与晋级阈值；未发生的流转是规则路径，不是抽签预测。当前战队放入真实战绩节点，未开赛不要生成虚构战绩。
- 抽签尚未公布的淘汰赛显示「待抽签席位」「本场胜者」等占位。没有正式上下半区映射时，后续轮次只画条件晋级关系并标注待抽签，不把按日期排序的比赛强行两两接成官方半区。
- 信息足够时从比赛结果推导胜者/败者，再核对下游双方；不把队名重复手写到多个位置，以免结果更新后图与赛程矛盾。

## 可用性与验收

优先用真实 DOM 比赛卡加 SVG/CSS 连线，文字可选中、战队可点击；不能用整张截图或生成图片替代可更新的比赛数据。图较宽时提供局部横向滚动与滚动提示，手机端保持队标、名称和比分可读，不把整张树缩成缩略图；另保留可访问的文本进程说明。

运行时宿主使用 `style-src 'self'` 与 `script-src 'self'`：卡片定位、节点状态样式写入包内外置 CSS，用稳定节点属性/类名关联；不要通过 `innerHTML` 注入 `style="left:…;top:…"`、内联样式表或事件处理器。先在相同 CSP 下检查每个节点的实际边界与连线端点，再到正式工具页确认；无 CSP 的本地文件预览可能掩盖所有节点重叠的问题。

按每个阶段记录视图类型和验证结果。至少检查一条胜者路线、一条败者路线、未知席位与后续轮次，截图必须实际出现连线和比赛卡；文本结果列表、空 SVG 或仅写赛制规则均不算晋级图验收。阶段不适合对阵树时说明所选替代进程视图，并验证它能看出晋级条件。
