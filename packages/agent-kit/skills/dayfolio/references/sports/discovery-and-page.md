# 需求梳理与页面选择

## 问影响结构的问题

从用户原话、已存在页面及已核实赛事资料填写已知信息，避免重复问用户。优先确定：

1. 具体赛事与届次、整届还是某个阶段/时间窗。
2. 使用目的：看赛程、理解晋级、研究表现、追踪特定对象。
3. 关注的队伍/选手，以及希望加的模块。

一般先给简短推荐，让用户删减。语言与时区已有上下文时沿用；没有时给合理默认。用户给出明确范围后直接制作，不再询问赛事已可查到的固定知识。重要歧义如男子/女子或个人/团体无法消除时先问，仍可并行核实来源。

生成前的配置摘要应简短：赛事/届次、参赛主体、阶段结构、核心模块、关注对象、数据范围/更新方式及交付位置。只规划时输出摘要与数据缺口，不写入 App；用户要求制作时摘要不增加审批关卡。

## 模块按适用性选择

| 模块 | 选择方式 |
| --- | --- |
| 赛程与比赛详情 | 默认主入口；阶段、日期、状态、关注对象筛选，主/客或双方语义按项目调整 |
| 赛制与进程 | 新用户强调解释，熟悉赛事者强调晋级形势；按规则选择榜、战绩组、树或成绩 |
| 参赛者总览 | 自动命名为选手、组合、战队、球队、国家队或代表团；团队赛事每队真实队标与介绍按 [队伍资料](team-profiles.md) 获取 |
| 人物与名单 | 实际检索并展示可查的本届名单、位置/角色、替补、来源与相关赛程；不要把当前名单写成历史阵容 |
| 技术统计 | 数据源支持后选项目适用指标，例如进球或逐局数据；不强加足球指标给电竞 |
| 评分 | 明确官方成绩、第三方表现分、AI 分析或用户打分，来源与量表分别展示 |
| AI 动态与分析 | 根据用户目的选择，标注来源、截止时间、事实与推断边界 |
| 来源与更新 | 独立视图，展示字段来源、覆盖和抓取状态，AI 提示词与整理状态 |
| 个性化 | 按需关注、收藏、日历导出；提醒/后台订阅仅在宿主真实支持且用户需要时配置 |

关注球员不等于只显示其所在队伍的介绍。用该届参赛关系关联赛程，转会与临时替补需要有时间范围。

## 页面行为

- 已确定双方的比赛，点击队伍名称或队徽打开队伍资料，点击比赛卡其余区域（时间、比分、状态及空白）打开这场比赛详情。收藏、关注、加入待办等独立操作保留本来语义，避免事件冒泡同时打开两个详情；提供可见焦点及 Enter / 空格操作，关闭详情保留原筛选和偏好。未定席位不冒充已确定对阵。
- 区分系列赛/总比分与子场结果，跨日期显示明确时区；以正式状态显示取消/延期。未知时间用「待公布」，不用午夜时间占位。
- 各阶段尽量按 [晋级图](progression-views.md) 显示适用的进程图，对阵树不隐去待定席位，综合赛事支持项目/小项过滤，不把所有项目平铺成一份巨大对阵表。
- 独立来源页面列出 API、官方页面、派生计算、AI 与用户输入；可选择对象复制完整提示词，结果带来源导入后能在对应资料页回读。
- 评分缺源时省略或显示待补，不生成看似精确的虚构评分。预测与已确认结果采用明确文字区分。
- 视觉按赛事身份和信息密度设计，保留用户已有页面语言；新建或更换视觉时遵循 [视觉生成与验收](visual-quality.md)，不要把「专业」固定成深蓝、足球队徽或某个布局。
- 关注/收藏用稳定 `pageId` 命名存储键，例如 `tododesk-sports:<pageId>:preferences`；不同工具可能共享协议 origin，不能只用 `favorites` 这样的全局键。
- 有有效快照时先可读，刷新失败显示当前范围的旧数据及时间；初始数据不是实时数据，不修改标签冒充实时。

## 单场比赛详情与 AI 补齐

- 基础区展示本届赛事、双方身份与真实队徽、北京时间、阶段/轮次、已核实比分和状态、场地、资料来源及核实时间；未知字段明确标注。比分按项目解释，足球区分常规/加时/点球（来源有提供时），电竞区分系列赛胜局与逐局成绩。
- 依据项目和当前状态选择内容：足球展示正式首发、已核实阵型与替补、进球/助攻、红黄牌、换人、VAR 等事件和可靠技术统计；LoL 展示 BO 局制、正式出场选手、逐局结果和时长、已核实版本/选边/BP、关键击杀或资源事件及可靠技术统计。其他项目选择对应的有效字段，不照搬足球栏目。字段缺少时说明尚未取得，不用默认零或虚构事件填充。
- 仅展示证据明确属于本场/本局的正式首发或出场名单，复用人物中文名、头像与详情；赛季名册不等于本场人员。已有正式名单必须读出并展示；预测、已过期预测和分析分别标明，不能混入确认事实。
- 单场详情提供固定文案「获取比赛信息」按钮，点击复制针对这场比赛的更新提示词，成功提示「复制完成，请去 AI 中更新这场比赛。」按钮本身不联网、不调用 AI、不更改事实或安排。优先使用宿主可用的即时复制方式；异步剪贴板接口需要有界超时与回退，避免等待权限而一直没有反馈。复制成功后恢复原提示词折叠状态；失败时展开可选中的完整提示词，明确提示手动复制，不能伪报完成。
- 提示词包含页面 ID、工具 ID、入口、届次、双方稳定 ID、比赛记录/提供方稳定 ID、比赛时间、请求时间、显示时区、现有资料截止、比分状态、适用官方来源与当前缺口；按项目要求首发/逐局名单、文字赛况和统计，并约束事实、预测与分析分开。保存结构与增量写回要求见 [数据获取与更新](data-and-update.md)。
- 文字赛况按来源自行概述，逐条保留时间标记、稳定事件 ID、来源、真实发布时间或 null、核实时间；缺少可靠来源就保留缺口，不整段复制直播文字。

## 验收

至少实际操作阶段/日期筛选、人物/队伍入口、来源页与提示词复制；对确定比赛分别点击队名、队徽、时间、比分和卡片空白，核对入口互不干扰，收藏/待办动作不误开详情。检查已有正式首发与缺少名单两种情况、按项目区分的栏目，以及「获取比赛信息」实际剪贴板内容是否只指向该场。复制成功和失败反馈都需准确。在宽窄两种屏幕检查溢出及可读性。更新再检查关注/收藏、页面 ID、非目标内容和文件是否保留。只有离线模拟验收时明确记录该边界，不声称已验证线上接口或正式安装。
