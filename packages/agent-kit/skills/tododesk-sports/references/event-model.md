# 赛事模型：按当届规则组合

## 识别维度

先建立赛事画像，维度彼此独立，不把它们做成只能二选一的总分类：

- 项目与赛事：足球、乒乓球、英雄联盟等；赛事品牌与具体届次/赛季必须分别记录。
- 赛事范围：单项或综合赛事。综合赛事可有项目、分项、小项、性别/年龄/量级与场地并行层级。
- 参赛主体：个人、双人组合、战队/俱乐部、国家队、代表团；同一赛事可以混合主体类型。
- 实体关系：运动员/选手、当届名单、所属队伍、赛区/国家、组合或代表团。历史名单按参赛届次保存，当前转会信息不覆盖历史参赛关系。
- 比赛层级：阶段 → 分组/轮次 → 对阵/系列赛 → 场/局/盘/回合。并非每项赛事都需所有层级。
- 页面范围：整届、某阶段、滚动时间窗、关注对象；记录原始时区和用户显示时区，使用带时区时间，允许开赛时间尚未确定。

「男乒」不等于单打；单打、双打、团体会改变主要实体与赛制。单人项目以选手为主，但国家、俱乐部仍可为辅助信息。奥运会总览与奥运男乒单打不是同一种页面范围。

## 阶段和晋级

用可组合的阶段和晋级关系描述，不枚举少数赛事名称决定页面：

| 赛制 | 进程视图 | 应核实的规则 |
| --- | --- | --- |
| 联赛、循环赛 | 积分榜/排名、轮次、晋级区 | 积分和同分规则、比赛场次是否一致 |
| 分组赛 | 分组榜、出线状态、必要的跨组比较 | 小组数量、出线名额、跨组名额与对阵映射 |
| 瑞士轮 | 按战绩分组、晋级/淘汰状态 | 配对与重赛限制、胜负阈值、不同轮次局制 |
| 单败淘汰 | 对阵树、晋级路径 | 种子、抽签、季军赛、单场/两回合/系列赛 |
| 双败淘汰 | 胜败者组及淘汰关系 | 落败去向、决赛与重置规则 |
| 计时/计分/多轮成绩 | 预赛/复赛/决赛成绩与晋级线 | 取最好或累计成绩、并列、无效成绩 |

淘汰赛不强行做积分榜，瑞士轮不强行排成没有规则依据的唯一名次。排名展示注明「小组/阶段/世界排名/页面窗口内统计」，不能混称。计算数据不全、同分规则未核实时优先采用官方排名或标明待核实。

对阵可以引用未决席位，如「A 组第一」「某系列赛胜者」「待抽签」。区分规则约束、可能路径和已确认对阵，不把算法猜测写成官方安排。

比赛状态应覆盖未定、待赛、进行中、结束、延期、中断、取消、弃权/判罚等真实需要。原结果更正与状态变更保留来源和时间，不能把所有异常视为 0:0。

## 三个主要验收案例

案例用于检验抽象，不是固定模板。执行时重查用户要求届次的官方规则。

- **LoL 世界赛**：区分战队与选手、赛区、位置，系列赛胜局与单局数据。阶段可能含入围、瑞士轮、淘汰赛，不同阶段可能使用不同局制；验证战绩分组、未知抽签及局制变更。不可默认官方开发者 API 覆盖职业电竞赛程。
- **欧冠**：区分俱乐部与国家队、联赛阶段与旧版小组赛、单场比分与两回合总比分；验证排名与晋级区、附加赛和后续淘汰路径。
- **世界杯**：先确认项目、国家队/俱乐部、男子/女子与届次；验证分组、跨组出线比较、淘汰树、季军赛。不能把往届规模或两回合规则套到另一届。

第一方核实入口示例（不是固定数据 API）：

- Riot：赛事官网及当届赛事规则，例 https://lolesports.com/en-GB/news/worlds-2026-primer 。
- UEFA：当季赛事规则，例 https://documents.uefa.com/r/Regulations-of-the-UEFA-Champions-League-2026/27/Article-13-Competition-stages-Online 。
- FIFA：当届赛事页面与竞赛规程，例 https://www.fifa.com/en/tournaments/mens/worldcup/canadamexicosa2026 。

补充用个人单打及多项目运动会检查主体/层级适配，避免三个团队案例通过后就声称已覆盖所有运动。
